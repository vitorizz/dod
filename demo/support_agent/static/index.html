dod · lineage for agent memory

A support agent whose memory spans four real systems
What the agent read and wrote, turn by turn read into the prompt retrieved during the turn

What you're looking at

A customer-support agent for an online store. Like real agents, it remembers things across conversations, in several different systems. dod records, every time the agent writes something, which items were in its context at that moment. That single record is what lets you trace a bad answer to its cause and clean up only what it affected.

The four systems (columns)

  • Conversation: each customer message the agent handled (LangGraph state).
  • Long-term memory: the company's policy handbook and notes about each customer (Postgres + pgvector, or in-memory).
  • Policy notes: policy updates the agent writes to files (Anthropic memory tool).
  • CRM: tickets and the replies actually sent to customers, in a separate server the agent reaches over MCP.

Rows and lines

Each row is one turn: a customer message, and everything the agent wrote while handling it. A line with a dot means a later turn read that box: it was in the agent's context when it wrote that row. Solid: it was in the prompt; dashed: it was retrieved during the turn.

The story

  1. Ben falsely claims the refund window was extended to 90 days (it's 30). The agent believes him and writes it down in refunds.md.
  2. Dev and Eli ask unrelated questions; answered correctly.
  3. Ana (45 days) and Chloe (50 days) ask for refunds. The agent reads refunds.md and wrongly approves both: replies, tickets, notes.
  4. Ana asks when her refund arrives; the agent confirms it from its note. The mistake has spread.

Try it

  1. Click Run the story (or send the story one message at a time with the dashed box in the chat).
  2. Click Chloe's wrong reply, then Where did this come from? Everything unrelated fades; the path leads back to Ben's message.
  3. Click Ben's message, then What came from this? to see everything it contaminated, in all four systems.
  4. Excise & regenerate: quarantine exactly that, then let the agent re-answer the affected customers from clean memory. The before/after shows up below the graph and in the chat.

dod never decides what is false: a person does, from the trace. dod makes "find everything derived from it, and remove only that" a query instead of a wipe.

dod · lineage for agent memory

A support agent whose memory spans four real systems
What the agent read and wrote, turn by turn → read into the prompt → retrieved during the turn

What you're looking at

A customer-support agent for an online store. Like real agents, it remembers things across conversations, in several different systems. dod records, every time the agent writes something, which items were in its context at that moment. That single record is what lets you trace a bad answer to its cause and clean up only what it affected.

The four systems (columns)

  • Conversation: each customer message the agent handled (LangGraph state).
  • Long-term memory: the company's policy handbook and notes about each customer (Postgres + pgvector, or in-memory).
  • Policy notes: policy updates the agent writes to files (Anthropic memory tool).
  • CRM: tickets and the replies actually sent to customers, in a separate server the agent reaches over MCP.

Rows and lines

Each row is one turn: a customer message, and everything the agent wrote while handling it. An arrow from a box into a later row means that turn read the box: it was in the agent's context when it wrote that row. Solid: it was in the prompt; dashed: it was retrieved during the turn. When you trace, the arrows flip and point back to where things came from.

The story

  1. Ben falsely claims the refund window was extended to 90 days (it's 30). The agent believes him and writes it down as a policy note.
  2. Dev asks about shipping: answered correctly, nothing to do with Ben.
  3. Ana asks to return an order delivered 45 days ago. The agent reads the note and wrongly approves it: a reply, a refund ticket, a note about her.
  4. Ana asks when her refund arrives; the agent confirms it from its note. The mistake builds on itself.

Then someone notices

Cleanup starts when a person finds a mistake. Open the Support lead tab in the chat and type @excise with what's right: “@excise The refund window is 30 days, not 90.” With a real model, the model reads your correction and its memory to find what contradicts it. It replies in the chat:

  1. What contradicts you: its memory about refunds, with the records that say something else ticked. Untick any that are right.
  2. What it would do: dod traces them to where they came from (Ben's message) and groups everything built on it: notes to fix, tickets to cancel, customers to notify, conversations kept on record, and what's untouched.
  3. Fix it: the correction is written as a note, the ticket is cancelled in the CRM, the wrong records stop being read (kept, not deleted), and Ben and Ana get corrected replies. Everything it writes traces back to the correction.

You can still click any box to trace it (where did this come from?) or see what came from it.

dod never decides what is false: a person does. dod makes “find everything built on it, and fix only that” a query instead of a wipe.
